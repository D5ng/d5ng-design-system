# FF 리뷰

기준의 정본은 `docs/ff/`다. 이 파일은 순서와 결과 형식만 다룬다. 항목 요지를 여기에 옮겨 적지 않는다.

## 1. 범위

```bash
git diff --stat develop...HEAD
git diff develop...HEAD -- 'packages/**/*.ts' 'packages/**/*.tsx'
```

- 코드(`.ts`·`.tsx`)와 공개 API(props 타입, export)를 본다. 자동 생성 파일(`packages/tokens/src/generated`)은 뺀다
- 스토리와 테스트는 쓰는 법이 어색하다는 신호로만 읽는다. 스토리 문구 자체는 지적하지 않는다
- 사용자가 파일이나 PR을 지정하면 그 범위만 본다

## 2. 항목 고르기

`docs/ff/README.md` 목차 표의 "읽을 때 묻는 질문"을 변경마다 던져서 걸리는 항목만 고른다. 걸리지 않은 항목을 살펴봤다고 쓰지 않는다.

## 3. 읽고 판단하기

- 고른 항목 파일을 끝까지 읽는다. 특히 "적용하지 않는 경우", "다른 항목과의 상충", "React 컴포넌트 props API에 적용"을 본다
- 지적은 **변경 비용**으로 쓴다. 어떤 변경이 생기면 무엇을 함께 고쳐야 하는지 적는다. "더 깔끔하다"만으로는 지적하지 않는다
- 두 항목이 부딪히면 가독성(R)을 먼저 보고, 어느 쪽을 골랐는지 적는다
- README의 "API를 판단할 때의 경계"를 넘지 않는다. prop 철자나 boolean과 enum의 선택 자체는 FF로 판정하지 않는다
- `docs/components/<이름>.md`에 이미 정한 결정은 다시 지적하지 않는다. 새 근거가 있으면 "다시 볼 것"으로 따로 적는다
- `.claude/rules/`나 lint가 정한 것과 겹치면 그 규칙을 따른다

## 4. 결과

한 메시지에 표 하나로 보여 주고 멈춘다. 고치는 것은 사용자와 정한 뒤에 한다.

| #   | 항목 | 위치      | 지적(어떤 변경 때 비용이 생기나) | 제안 | 추천 |
| --- | ---- | --------- | -------------------------------- | ---- | ---- |
| 1   | R6   | `파일:줄` |                                  |      |      |

- 추천은 "반영" 또는 "반영 안 함 + 이유 한 줄"이다
- 지적이 없으면 "지적 없음"과 살펴본 항목 번호만 쓴다
- PR 코멘트로 남기지 않는다. 반영하지 않기로 한 이유 중 남길 만한 것은 `docs/components/<이름>.md`나 PR 본문에 쓴다
