# 코드 주석

주석도 ~요체로 핵심만 짧게 쓴다. 한 줄에 한 가지만 말하고 "~하는 용도다", "~하므로" 같은 군더더기는 뺀다. 대상 바로 위에 둔다.

- 예: `// 컴포넌트를 소스에서 읽어서 .css.ts를 처리할 플러그인이 필요해요.`

주석은 종류마다 읽는 사람이 다르다. `//`는 코드를 고치는 사람이, JSDoc은 쓰는 쪽이 읽는다(Storybook 문서 표와 AI 매니페스트로 나간다).

| 종류      | 쓰는 곳                                                | 쓰는 내용                                                                                    |
| --------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `//`      | 코드 안                                                | 왜만 쓴다: 이유, 제약, 버린 대안. 코드가 하는 일을 다시 말하지 않는다                        |
| `/** */`  | 공개 API(컴포넌트, props, export한 함수·타입)와 스토리 | 무엇이고 언제 쓰나, 동작 계약 한 줄, `@default`. 코드는 백틱으로 감싼다. 내부 함수엔 안 쓴다 |
| 우회 코드 | 브라우저 버그, 라이브러리 한계를 피하는 곳             | 이유, 근거 링크, 언제 지울 수 있는지                                                         |
| 구역 주석 | 긴 파일을 부분으로 나눌 때                             | `// ---- 부분 이름` 한 줄. 컴포넌트가 여럿인 파일은 Radix처럼 부분(컴포넌트) 이름을 쓴다     |

쓰지 않는 것:

- 코드를 그대로 읽어 주는 주석
- 할 일("나중에", "~할 예정"): 이슈로 만들고, 주석에는 지금 왜 이런지만 남긴다. 이슈를 가리킬 땐 `#12에서 다뤄요`처럼 번호를 쓴다
- 변경 이력("예전엔 ~였어요"), 작성자, 날짜: git과 PR에 남는다
- 주석 처리한 코드

`//` 주석 앞에 머리말을 붙이지 않는다. 할 일이 머리말 뒤에 숨기 쉽다(예: `NOTE`로 시작하는 정하지 못한 질문). 아래 여섯 개는 lint(`no-warning-comments`)가 막는다.

| 머리말                 | 대신                                                          |
| ---------------------- | ------------------------------------------------------------- |
| `TODO`, `FIXME`, `XXX` | 이슈로 만들고 번호만 남긴다                                   |
| `HACK`                 | 우회 코드 형식으로 쓴다: 이유, 근거 링크, 언제 지울 수 있는지 |
| `NOTE`, `WARNING`      | 무엇이 왜 그런지 문장으로 쓴다                                |

JSDoc 태그는 이것만 쓴다.

| 태그                 | 규칙                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| `@default`           | 기본값이 있는 prop엔 꼭 쓴다. Storybook 문서 표가 읽는다. `@defaultValue`와 섞지 않는다 |
| `@deprecated`        | 없애기 전에 쓴다. 대신 쓸 것과 없어질 버전을 함께 적는다                                |
| `@see`               | Figma 노드나 관련 문서 링크가 필요할 때만 쓴다                                          |
| `@param`, `@returns` | export한 함수에서 이름과 타입만으로 뜻이 안 보일 때만 쓴다                              |
| `@example`           | 쓰지 않는다. 예시는 스토리가 맡는다                                                     |

특수 주석에는 이유를 붙인다.

- `// eslint-disable…`: 끄는 규칙과 이유. lint가 설명을 강제한다
- `// @ts-expect-error`: 이유를 붙이고, `@ts-ignore`는 쓰지 않는다. 둘 다 lint(`strictTypeChecked`)가 강제한다
- `// prettier-ignore`: 이유를 붙인다. lint가 못 잡아서 리뷰에서 본다
- `/* @__PURE__ */`: 빌드 도구가 읽는 표시라 그대로 둔다
